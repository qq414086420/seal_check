二、问题

表现章面细节仍会造成漏检和误报

现有基线中，章面与主体名称核对的负例召回为 72.2%（187/259）；手写／打印判别的负例精确率为 37.1%。本次测试也出现截断名称未识别和正常名称被误判的情况。

示例为合成数据；公司名称与标准答案来自数据集构造标注。本报告列出原图文件名，便于在数据集中查找。

P1评分脚本存在解析和分组错误

在 scripts/run_eval.py 中，JSON 解析失败后按选项顺序进行子串匹配。选项为“一致 / 不一致”时，非 JSON 回复“不一致”会先匹配到“一致”，且不记为解析失败。另一方面，预测记录保存 group，汇总函数却只读取 qtype 或 task，实际运行结果可能全部落入 unknown。

源码位置：run_eval.py：解析与分组。以上为静态代码核查，当前环境未执行原 Python 跑分脚本。

P1异常答案可能抬高负例精确率；T1 统计有字段错误

answer_model=None 时，脚本仍可能将其当作负例报警；若该题标准答案为负例，还会算入精确率分子。T1 漏检统计读取不存在的 answer 字段，修复分组后可能触发 KeyError。

源码位置：run_eval.py：精确率与漏检统计。

P2报告口径、数据版本及任务边界需要统一

仓库原报告出现“87.9%（3824/0）”：复算正确值是 3363/3824。当前清单有 782 图，部分说明文档仍写 758 图或旧题数。真实图 T4 的 63 题全部为正例，无法衡量真实场景抓假召回。

合成“手写”签名由手写字体渲染，与真实手写、扫描后打印的签名来源判断存在差距。真实网络图的真章标签为弱标签，因此现有结果不宜直接作为实际印章真伪鉴定结论。

源码位置：score_agent_run.py：报告格式；gen_synthetic.py：签名字体渲染。

三、建议

  1. 优先修正解析与预测字段

    只接受合法 JSON 对象，检查 answer 是否完整等于某个选项；格式异常单独记录并计入总题数。统一保存并读取 task、qtype、answer_model，避免不同阶段使用不同字段名。

    def parse_answer(raw, choices):
    try:
        value = json.loads(raw).get("answer")
        return (value, False) if value in choices else (None, True)
    except (ValueError, AttributeError):
        return None, True

def group_key(row):
    return row.get("qtype") or row.get("task") or row.get("group") or "unknown"

    回归示例：非 JSON 的“不一致”应返回 (None, True)；有效 JSON {"answer":"不一致"} 应返回 ("不一致", False)。

  2. 修正统计口径并增加回归检查

    负例精确率的分母只统计有效负例预测；解析失败不计作报警。T1 漏检使用 answer_model 字段，报告直接写入 correct / total。测试至少覆盖漏检、误报、无效 JSON、非法选项、空分母、重复题号及断点续跑混入旧题。

  3. 统一版本与可复现信息

    从题集和清单自动生成图片数、题数及标签分布，统一 README、使用指南和报告。每次运行记录数据版本、图片哈希、提示词、模型标识及参数；续跑前校验这些信息，只对当前题集计算成绩。

    本次固定版本：782 图、5415 道全量题；其中 T4 全量 3824 题，T4 平衡子集 1632 题。

  4. 补充真实场景负例并细化任务

    在保留来源及复核依据的前提下，补充真实主体不一致、扫描件二次打印、电子签、低清遮挡等样本；分别报告误报率和负例召回。将名称一致性、图像篡改迹象、签名字体风格与实际真实性判断分别定义。

    目前 T4-real 的 63 题全部为正例，仅能观察正例被误判的情况。

  5. 按图和底图组织评测结果

    同时输出逐题结果、分题型负例召回、精确率、F1 与图级全对率；同一底图及其变体放在同一分组。模型输入仅包含匿名图片、题干和选项，标准答案与来源路径留在评分端。

    原基线 T4 逐题准确率为 87.9%，图内全部答对为 242/496（48.8%）。两项指标应结合阅读。
